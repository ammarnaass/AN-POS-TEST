## 1. المقدمة ونظرة عامة

يهدف هذا الدليل إلى توثيق البنية الهندسية والبرمجية لثلاث ميزات رئيسية في تطبيق الهاتف المحمول (`mobile-rn`) لنظام **AN POS**، بما يضمن التطابق الكامل (100% Feature Parity) مع تطبيق سطح المكتب (Desktop Electron):
1. **نظام العبوات (Packs):** التعامل مع كراتين وحزم الجملة كوحدات بيع مستقلة مشتقة من مخزون التجزئة.
2. **النسخ الاحتياطي الشامل (Full Backup & Restore):** تصدير واستيراد كافة البيانات مع الصور والشعار، بالإضافة إلى الجلب المباشر عبر شبكة الـ Wi-Fi من الكمبيوتر المقترن.
3. **قالب مبيعات الجملة (Wholesale Print Template):** تخصيص وطباعة فواتير الجملة بصيغتي A4 الورقية والإيصالات الحرارية (Bluetooth ESC/POS).

## 2. المحور الأول: نظام عبوات الجملة والباقات

### 2.1 بنية البيانات ومخطط جدول `packs`

يُخزن تعريف العبوات في جدول `packs` داخل قاعدة بيانات SQLite المحلية (`react-native-nitro-sqlite`):

```sql
CREATE TABLE IF NOT EXISTS packs (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  barcode TEXT,
  pack_price REAL NOT NULL,
  items TEXT NOT NULL DEFAULT '[]', -- JSON String: Array<{ productId: string, name?: string, qty: number }>
  is_active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

#### نموذج المكونات (`items` JSON):
```json
[
  {
    "productId": "prod-101",
    "name": "حليب صومام 1ل",
    "qty": 10
  }
]
```

---

### 2.2 معادلات احتساب الرصيد والتكلفة وهامش الربح

لا يتم تخزين رصيد فيزيائي منفصل للعبوة، بل يُحسب لحظياً وديناميكياً من رصيد المنتجات الأصلية المكونة لها:

1. **الرصيد المتاح للعبوة (Available Pack Stock):**
   $$\text{AvailablePacks} = \min_{i} \left( \left\lfloor \frac{\text{Stock}(Product_i)}{\text{PackQty}_i} \right\rfloor \right)$$
   *إذا كان منتج العبوة به 25 قطعة، والعبوة تحتوي 10 قطع، فإن المخزون المتاح هو 2 عبوة (والباقي 5 قطع لا تكفي لتشكيل عبوة ثالثة).*

2. **تكلفة العبوة الإجمالية (Total Pack Cost):**
   $$\text{TotalCost} = \sum_{i} \left( \text{CostPrice}(Product_i) \times \text{PackQty}_i \right)$$

3. **هامش الربح (Profit Margin %):**
   $$\text{Margin\%} = \frac{\text{PackPrice} - \text{TotalCost}}{\text{PackPrice}} \times 100$$

4. **وفر المشتري مقارنة بالتجزئة (Buyer Savings):**
   $$\text{BuyerSavings} = \left( \sum_{i} \text{RetailPrice}(Product_i) \times \text{PackQty}_i \right) - \text{PackPrice}$$

### 2.3 واجهة إدارة وتعديل العبوات (`PacksScreen.tsx`)

المسار: `mobile-rn/src/features/promotions/PacksScreen.tsx`
- **إنشاء عبوة جديدة:** إدخال الاسم، الباركود (يدوياً أو عبر الكاميرا `CameraScanner`)، وسعر العبوة، واختيار الأصناف والكميات.
- **تعديل العبوة الحالية (`EditPackModal`):** الضغط على زر التعديل بجانب أي عبوة يفتح النافذة بكافة بياناتها ومكوناتها مع زر الحفظ المباشر.
- **شريط التحليل المالي اللحظي:** يعرض التكلفة الإجمالية، المخزون المتاح، هامش الربح، والوفر التقديري للمشتري.
- **عرض البطاقة المتقدم:** إظهار شارة `• المتاح: X عبوة` خضراء أو حمراء، مع عدد القطع `×10 قطعة` وسعر البيع.

---

### 2.4 دورة المبيعات والخصم المباشر للمكونات في نقطة البيع (`PoSScreen.tsx`)

المسار: `mobile-rn/src/features/pos/PoSScreen.tsx`
1. **في شاشة البيع:**
   - تظهر العبوات في قائمة الأصناف باسم `📦 اسم العبوة (×N)`.
   - يتم التحقق من توفر رصيد تشكيل العبوة، وإذا كان الرصيد صفراً يتم حظر الإضافة وتنبيه البائع.
   - في السلة، يتم تقييد كمية العبوات بحيث لا تتجاوز إجمالي العبوات الممكنة.
2. **عند إتمام البيع (`completeSale`):**
   - يتم التعرف على بند العبوة عبر `item.isPack`.
   - يتم جلب مكونات العبوة من جدول `packs`.
   - لكل مكون، يتم خصم الكمية من المنتج الأصلي:
     $$\text{Deduction} = \text{SoldPacks} \times \text{ComponentQty}$$
   - تسجيل حركة مخزنية خارجة في `stock_movements` و `stock_movements_v2` مع ذكر رقم الفاتورة واسم العبوة، ومزامنتها مع الخادم عبر `syncEngine`.

### 3.2 معيار حفظ واسترجاع الصور بنسبة 100%

- تُخزن صور المنتجات في حقل `products.image` وشعار المتجر في `settings.shop_logo` كسلاسل نصية بصيغة `data:image/jpeg;base64,...` أو `data:image/png;base64,...`.
- عند إنشاء النسخة الاحتياطية، لا يتم اقتطاع أو إزالة هذه الحقول، بل يتم تصديرها بالكامل داخل كائن البيانات `data.products`.
- عند الاسترجاع، تعود الصور مباشرة إلى قاعدة بيانات SQLite لتعمل الواجهة فوراً دون الحاجة للاتصال بالإنترنت.

### 3.4 خدمة النسخ في الهاتف (`backupService.ts`)

المسار: `mobile-rn/src/services/backup/backupService.ts`
الوظائف البرمجية الأساسية:
- `getMobileLiveStats()`: حساب إحصائيات قاعدة بيانات الهاتف الحالية وعدد الصور المحفوظة والحجم التقريبي.
- `generateMobileBackup()`: تصدير كافة الجداول الـ 25 وبناء كائن `metadata`.
- `inspectBackupContent(jsonStr)`: فحص سلامة ملف JSON وتحديد تفاصيله وعدد الأصناف والصور قبل إدراجه.
- `executeMobileRestore(backupData, mode)`:
  - **نمط الدمج الذكي (`merge`):** يستخدم `db[table].bulkPut()` أو `INSERT OR REPLACE` لتحديث السجلات الحالية وإضافة الجديدة دون حذف أي سجلات أخرى.
  - **نمط الاستبدال النظيف (`clean`):** تفريغ الجداول بترتيب عكسي لمنع أخطاء المفاتيح الأجنبية، ثم إدراج بيانات النسخة.
- `fetchBackupFromDesktop()`: الاتصال بعنوان IP لخادم سطح المكتب المسجل في `AnposSecureStore` وطلب المسار `/api/backup/export`.

### 3.5 آلية الجلب المباشر عبر الشبكة المحلية (LAN Fetch from Desktop)

عندما يكون الهاتف مقترناً بجهاز الكمبيوتر في نفس شبكة الـ Wi-Fi:
1. يقرأ الهاتف عنوان خادم سطح المكتب من `AnposSecureStore.get('anpos_server_url')`.
2. يرسل طلب HTTP GET:
   `GET http://<DESKTOP_IP>:<PORT>/api/backup/export`
3. يستجيب خادم Electron في الكمبيوتر بالنسخة الاحتياطية الكاملة.
4. يفتح الهاتف مباشرة **نافذة فحص ومعاينة النسخة (Inspection Modal)** ليراجعها المستخدم ويضغط "تأكيد واسترجاع".

---

### 3.6 واجهة ونافذة المعاينة قبل الاسترجاع (`BackupRestoreScreen.tsx`)

المسار: `mobile-rn/src/features/settings/BackupRestoreScreen.tsx`
- **البانر العلوي:** يعرض إحصائيات النظام الحية وشارة الأمان: `الصور محفوظة 100%`.
- **كارت التصدير الشامل:** يولد ملف `.anpos.json` ويفتح قائمة المشاركة الأصلية لنظام الهاتف (`Share.share`) لحفظه في Google Drive أو إرساله عبر WhatsApp.
- **كارت جلب النسخة عبر الشبكة (LAN):** كارت مخصص بجانب أيقونة Wi-Fi لجلب نسخة الكمبيوتر بلمسة واحدة.
- **نافذة الفحص والمعاينة (Inspection Modal):**
  - تظهر فور اختيار أو جلب أي ملف.
  - تعرض جدولاً يوضح: عدد المنتجات، عدد الصور المكتشفة، عدد فواتير المبيعات، وقوالب الطباعة.
  - خيار اختيار نمط الاسترجاع: (دمج ذكي vs استبدال كامل).
  - خيار أخذ نسخة وقائية سريعة قبل بدء الاسترجاع.

## 4. المحور الثالث: قالب فاتورة البيع بالجملة

### 4.1 مفتاح المستند `wholesale-invoice` والترجمات المعتمدة

المفتاح الموحد في النظام: `'wholesale-invoice'`
الترجمات المعتمدة بحسب لغة الطباعة في `mobile-rn/shared/services/templateTranslator.ts`:
- **العربية (`ar`):** `فاتورة مبيعات جملة (Gros)`
- **الفرنسية (`fr`):** `FACTURE DE VENTE EN GROS`
- **المزدوجة (`ar-fr`):** `فاتورة جملة / FACTURE GROS`
- **الإنجليزية (`en`):** `WHOLESALE INVOICE`

---

### 4.2 القالب الافتراضي `default-wholesale-invoice-a4`

المسار: `mobile-rn/shared/services/defaultTemplates.ts`
- **المقاس:** A4 (210×297 ملم) أو 80mm حراري.
- **عناصر الترويسة:** شعار المتجر، الاسم التجاري، أرقام السجل التجاري (RC, NIF, NIS, ART).
- **بيانات الزبون:** اسم العميل، الهاتف، العنوان، الرصيد السابق، الدفعة المسددة، والرصيد المتبقي.
- **جدول بنود الجملة:**
  - اسم الصنف والعبوة (مثل `حليب صومام - كرتونة ×10`).
  - الكمية بالعبوات أو القطع.
  - سعر بيع الجملة.
  - المجموع الفرعي ونسبة الخصم وضريبة القيمة المضافة.
- **التذييل:** التوقيع والختم وعبارة الشكر.

---

### 4.3 إسناد وتخصيص القوالب (`TemplateAssignmentsModal.tsx`)

المسار: `mobile-rn/src/features/print/TemplateAssignmentsModal.tsx`
- يدرج مستند `wholesale-invoice` (فاتورة جملة) كعنصر مستقل ضمن قائمة إسناد القوالب.
- يستطيع المستخدم تخصيص قالبين:
  1. قالب افتراضي للطباعة الرسمية الورقية ومشاركة الفاتورة كـ PDF.
  2. قالب إيصال حراري (80 ملم) لطباعة الوصل الميداني للعميل عبر طابعة البلوتوث المحمولة.

---

### 4.4 المعاينة المباشرة والطباعة الحرارية والبلوتوث ومشاركة PDF

المسار: `mobile-rn/src/features/print/InvoicePrintPreviewModal.tsx`
1. عند إنهاء بيع بالجملة (`saleMode === 'wholesale'`) في شاشة POS، تُفتح نافذة المعاينة ممررة `sampleDocType="wholesale-invoice"`.
2. تجلب النافذة القالب المسند لفاتورة الجملة وتطبق عليه الترجمات المناسبة للغة المختارة.
3. تتيح النافذة:
   - الطباعة المباشرة عبر طابعة البلوتوث المقترنة (`react-native-ble-plx` عبر أوامر ESC/POS).
   - خيار إرسال أمر الطباعة لخادم سطح المكتب المقترن عبر الشبكة (`printViaDesktop`).
   - معاينة كاملة لملف الفاتورة قبل تسليمها للعميل.
